# 留存功能技术补充

本文档是 `CODE_WIKI.md` 的补充，专门定义留存功能（每日小任务、习惯热力图、连续打卡）的技术实现。CODE_WIKI 为主架构文档，本文档只覆盖留存相关的新增表、接口和逻辑。

功能需求见 `03-用户留存设计.md`。

---

## 1. 数据模型新增

### 1.1 daily_tasks（每日小任务）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | |
| user_id | bigint | 外键 → users |
| task_date | date | 任务对应日期 |
| task_content | varchar(50) | 任务文案，如"午餐加一份绿叶菜" |
| task_dimension | varchar(10) | 维度：饮食 / 饮水 / 睡眠 / 运动 |
| source | varchar(10) | 来源：ai（卡片轮播）/ preset（预设池） |
| completed | boolean | 是否完成，默认 false |
| completed_at | datetime | 完成时间，可空 |

唯一约束：`(user_id, task_date)` —— 每人每天一条任务。

### 1.2 task_pool（预设任务池）

种子数据表，通过 migration 初始化。供免费用户和 AI 卡片周期结束后取任务。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | |
| main_goal | varchar(20) | 对应用户主目标 |
| dimension | varchar(10) | 维度：饮食 / 饮水 / 睡眠 / 运动 |
| content | varchar(50) | 任务文案 |

数据量要求：每个主目标下每个维度 ≥ 30 条，避免重复疲劳。

### 1.3 热力图与连续打卡：不建新表

热力图和连续打卡的数据来源全部来自现有表的实时聚合，不新增持久化表：

| 维度 | 数据来源 |
|---|---|
| 饮食记录 | `diet_records`（当日有记录即标记） |
| 饮水打卡 | `lifestyle_records` where record_type='water' |
| 运动记录 | `lifestyle_records` where record_type='exercise' |
| 睡眠记录 | `lifestyle_records` where record_type='sleep' |
| 今日小任务 | `daily_tasks` where completed=true |

**性能说明：** MVP 阶段（<1000 用户）按用户 + 日期范围实时聚合查询，成本可接受。用户量增长后，再引入 `daily_activity`（user_id, activity_date, 各维度布尔位）日聚合表优化，本期不做（YAGNI）。

## 2. 核心逻辑

### 2.1 每日小任务生成（懒生成）

不使用定时任务。用户当天首次请求 `GET /api/v1/task/today` 时触发：

1. 查 `daily_tasks` 当日是否已有记录 → 有则直接返回
2. 无记录则生成一条：
   - **有 AI 初始卡片的用户**（含会员）：从卡片"7 天小行动"的 3-5 条习惯中，按 `卡片生成后天数 % 习惯数量` 轮播取一条，`source=ai`
   - **免费 / 无卡片用户**：从 `task_pool` 按用户主目标随机取一条，`source=preset`
3. 写入 `daily_tasks` 并返回

轮播保证本周内 3-5 个习惯交替出现，不会天天同一个。第 8 天起（卡片 7 天周期结束）转入 `task_pool` 取任务。

### 2.2 任务打卡

`POST /api/v1/task/today/complete` 将当日 `daily_tasks` 记录的 `completed` 置为 true，记录 `completed_at`。已完成再次调用幂等返回。

### 2.3 连续打卡（streak）

实时计算，定义"活跃日"= 当日在任意维度有记录（饮食/饮水/运动/睡眠/任务完成任一）：

- **当前连续天数**：从今天向前数连续活跃日
- **宽容机制**：每自然周允许 1 天空缺不中断 streak
- **历史最高**：遍历活跃日序列计算最大连续段
- 计算结果可缓存到 Redis（键 `streak:{user_id}:{date}`，当天有效），减少重复计算

## 3. API 接口新增

| 模块 | 方法 | 路径 | 功能 |
|---|---|---|---|
| 任务 | GET | `/api/v1/task/today` | 获取今日小任务（懒生成） |
| 任务 | POST | `/api/v1/task/today/complete` | 任务打卡完成 |
| 留存 | GET | `/api/v1/heatmap` | 习惯热力图数据 |
| 留存 | GET | `/api/v1/streak` | 连续打卡天数（当前 + 历史最高） |

### 3.1 GET /api/v1/task/today

响应：

```json
{
  "code": 0,
  "data": {
    "task_date": "2026-06-03",
    "task_content": "午餐加一份绿叶菜",
    "task_dimension": "饮食",
    "completed": false
  }
}
```

### 3.2 GET /api/v1/heatmap

请求参数：`weeks`（可选，免费默认上限 4，会员上限 12）

后端根据会员状态裁剪：
- 免费版：最近 4 周，3 个维度（饮食 / 饮水 / 睡眠）
- 会员版：最近 12 周，5 个维度（含运动 / 今日小任务）

响应：

```json
{
  "code": 0,
  "data": {
    "dimensions": ["饮食", "饮水", "睡眠"],
    "days": [
      { "date": "2026-05-20", "饮食": true, "饮水": true, "睡眠": false },
      { "date": "2026-05-21", "饮食": false, "饮水": true, "睡眠": true }
    ]
  }
}
```

冷启动：注册不足 7 天的用户，`days` 返回空，前端展示"开始记录第 N 天"文案（见 `03-用户留存设计.md` §2.4）。

### 3.3 GET /api/v1/streak

响应：

```json
{
  "code": 0,
  "data": {
    "current_streak": 12,
    "max_streak": 21
  }
}
```

## 4. 免费 vs 会员差异汇总

| 功能 | 免费版 | 会员版 |
|---|---|---|
| 每日小任务来源 | 预设任务池随机 | AI 卡片习惯轮播 |
| 热力图历史 | 最近 4 周 | 最近 12 周 |
| 热力图维度 | 3 个（饮食/饮水/睡眠） | 5 个（含运动/任务） |
| 连续打卡 | 支持 | 支持 |
