## 3. 数据库设计

### 3.1 核心表结构

```sql
-- 用户表
users: id, openid(unique), unionid, nickname, avatar_url,
       is_member, member_expire_at, created_at, updated_at

-- 用户档案表
user_profiles: id, user_id(FK), gender, birth_year, height, weight,
               main_goal, dietary_preferences(JSON), lifestyle_answers(JSON),
               created_at, updated_at

-- 饮食记录表
diet_records: id, user_id(FK), record_date, meal_type, content_type,
              text_content, image_url, ai_feedback(JSON), created_at, updated_at

-- 生活方式记录表
lifestyle_records: id, user_id(FK), record_date, record_type,
                   value, notes, created_at, updated_at

-- 每日完成度表
daily_completion: id, user_id(FK), record_date, completion_status, created_at, updated_at

-- AI生成内容表（持久化）
ai_generated_content: id, user_id(FK), content_type, content(JSON),
                      week_start_date, created_at, updated_at

-- 每周感受反馈表
weekly_feedback: id, user_id(FK), week_start_date,
                 energy_level, sleep_quality, digestion_status, created_at, updated_at

-- AI问答记录表
qa_records: id, user_id(FK), question, answer,
            context_snapshot(JSON), created_at, updated_at

-- API调用日志表
api_call_logs: id, user_id(FK), endpoint, input_tokens, output_tokens,
               cost, response_time, status, created_at, updated_at
```

### 3.2 Redis缓存键设计

```
user:profile:{user_id}                        # 用户档案缓存（1小时）
ai:initial_advice:{user_id}                   # 初始建议（持久）
ai:weekly_report:{user_id}:{week_start_date}  # 周小结（持久）
qa:dedup:{user_id}:{question_hash}            # 问答去重（5分钟）
limit:diet_feedback:{user_id}:{date}          # 饮食反馈次数限制
limit:qa:{user_id}:{date}                     # 问答次数限制
queue:weekly_report                           # 周小结任务队列（List）
```

### 3.3 关键索引

```sql
CREATE INDEX idx_openid ON users(openid);
CREATE INDEX idx_user_date ON diet_records(user_id, record_date);
CREATE INDEX idx_user_date_type ON lifestyle_records(user_id, record_date, record_type);

CREATE INDEX idx_weekly_report ON ai_generated_content(user_id, week_start_date);

```

## 4. API接口设计

### 4.1 基础规范

- Base URL: `https://api.yourdomain.com/v1`
- 认证方式: JWT Token（微信登录后颁发）
- 统一响应格式: `{ "code": 0, "message": "success", "data": {}, "timestamp": 123 }`

### 4.2 接口清单

```

GET    /api/v1/user/profile             # 获取用户档案

GET    /api/v1/user/member/status       # 获取会员状态
```

## 5. AI调用架构

### 5.1 四个触点实现模式

| 触点 | 调用方式 | 超时 | 失败处理 |
|------|---------|------|---------|
| 饮食反馈 | 同步非流式 | 3秒 | 降级返回"已记录" |
| 初始建议 | 同步流式 | 60秒 | 缓存已生成部分+重试入口 |
| 周小结 | 异步队列 | 30秒 | 降级为免费版模板 |
| AI问答 | 同步非流式 | 8秒 | 返回"AI暂时忙" |

### 5.2 成本控制实现

- **结果持久化**: 初始建议、周小结存数据库，复看不重新调用
- **频次限制**: 饮食反馈免费3次/天，问答免费3次/天
- **Prompt Cache**: DeepSeek原生支持，系统提示词缓存命中率>90%
- **请求去重**: 同一用户5分钟内相同问题返回缓存（二期）

### 5.3 关键词拦截（不走AI）

```python
BLOCKED_KEYWORDS = {
    "自残|轻生|不想活": "心理援助热线：010-82951332",
    "处方药|用药剂量": "建议咨询医生或药师",
    "怀孕.*用药|流产": "请及时就医咨询",
    "减肥药|泻药|催吐": "健康提醒 + 引导专业帮助"
}
```

### 5.4 周小结定时任务

```
每周日 20:00 触发
→ 查询活跃用户
→ 筛选本周记录>=3天的用户
→ 推入Redis队列
→ Worker处理：
    - 会员：AI生成（DeepSeek）
    - 免费：模板生成（规则引擎）
→ 发送微信订阅消息通知
```

## 7. 安全设计

- **认证**: 微信登录 → JWT Token（7天）+ Refresh Token（30天）
- **限流**: IP级别100次/分钟，用户级别1000次/小时
- **API安全**: HTTPS强制，CORS限制小程序域名，ORM防SQL注入
- **AI安全**: 关键词预拦截 + 禁用词检测 + 内容安全API接入

## 8. 监控指标

- API响应时间（P50/P95/P99）
- AI调用成功率及响应时间（按触点）
- 每用户每日AI调用次数（异常检测）
- AI输出格式错误率
- 数据库连接池状态
- Redis内存使用率

## 10. 技术决策摘要

| 决策 | 选择 | 理由 |
|------|------|------|
| 后端语言 | Python + FastAPI | AI集成友好，异步性能好 |
| 数据库 | MySQL + Redis | 关系型稳定 + 缓存层 |
| 部署 | Docker + 云服务器 | 环境一致性，易于运维 |
| 前端 | Taro (React) | 小程序优先，未来可扩展Web |
| AI调用 | 混合模式（同步+异步队列）| 快触点同步，慢触点队列 |
| 代码组织 | 领域驱动模块化 | 业务边界清晰，易于扩展 |
| AI成本控制 | 核心优先（持久化+限频+Cache）| MVP阶段轻量，二期再优化 |
