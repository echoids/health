# 用户留存设计

本文档定义两个核心留存机制：**每日小任务**（解决"每天为什么打开"）和**习惯热力图**（解决"为什么不想放弃"）。

产品价值观前提：本产品定位是**健康生活助手**，不是减肥工具或健身日记。所有设计必须围绕健康习惯养成，而非体重/身材目标。

---

## 1. 每日小任务

### 1.1 机制说明

用户每天进入 app，首屏展示 1 条"今日小任务"。任务来源于用户的初始建议卡片（AI 触点 2），由后端从卡片的"7 天小行动"中按顺序拆出，每天推送 1 条。

用户完成后点击打卡，任务标记为完成。未完成不作任何惩罚，不影响 streak。

### 1.2 任务池设计原则

任务必须覆盖四个维度，不能只围绕饮食/体重：

| 维度 | 示例任务 |
|---|---|
| 饮食 | 午餐加一份绿叶菜 |
| 饮水 | 上午喝够 3 杯水 |
| 睡眠 | 今晚 11 点前上床 |
| 运动/活动 | 饭后散步 10 分钟 |

**文案原则：**
- 用"增加""尝试""加一份"，不用"减少""控制""少吃"
- 任务必须是今天能做到的行为级动作（可打勾）
- 不出现热量、体重、BMI 等数值

### 1.3 任务来源优先级

1. **AI 生成任务**（优先）：从初始建议卡片的"7 天小行动"字段拆出，按顺序每天推送 1 条
2. **规则化补充任务**：7 天用完后，根据用户主目标从预设任务池随机选取，避免重复
3. **预设任务池**：按用户主目标分类，每类 30 条以上

### 1.4 免费 vs 会员

| | 免费版 | 会员版 |
|---|---|---|
| 每日任务 | 预设任务池随机 | AI 个性化任务 |
| 任务来源 | 按主目标分类的静态池 | 初始建议卡片 + AI 动态调整 |

## 2. 习惯热力图

### 2.1 机制说明

展示用户过去 N 周的习惯打卡记录，类似 GitHub 贡献图的格子形式。用户看到自己坚持的时间越长，越不愿意放弃。

### 2.2 展示维度

热力图追踪以下维度，每个维度独立一行：

| 维度 | 数据来源 | 说明 |
|---|---|---|
| 饮食记录 | 饮食记录提交次数 | 当日有记录即标记 |
| 饮水打卡 | 打卡模块 | 当日打卡即标记 |
| 运动记录 | 打卡模块 | 当日有运动记录即标记 |
| 睡眠记录 | 打卡模块 | 当日有睡眠记录即标记 |
| 今日小任务 | 每日小任务完成状态 | 当日完成即标记 |

**体重不在热力图中展示**，体重趋势作为独立的可选模块，和"精力感受""睡眠质量"平级，用户可自行决定是否关注。

### 2.3 视觉规则

- 格子颜色：当日全部维度打卡 → 深色；部分打卡 → 中色；未打卡 → 浅灰
- 展示范围：默认展示最近 12 周
- 不展示具体数值，只展示"做了 / 没做"的状态
- 不设"完美周""完美月"之类的完成率排名，避免制造焦虑

### 2.4 冷启动处理

前两周数据少，热力图会很空。处理方式：
- 前 7 天不展示热力图，只展示"开始记录第 N 天"文案
- 第 8 天起展示热力图，配文案"你已经坚持 X 天了"

### 2.5 免费 vs 会员

| | 免费版 | 会员版 |
|---|---|---|
| 热力图历史 | 最近 4 周 | 最近 12 周 |
| 维度数量 | 3 个（饮食/饮水/睡眠） | 全部 5 个维度 |

## 3. 连续打卡（辅助机制）

作为附加机制，不作为核心留存手段。

- 展示连续记录天数（streak）
- **宽容机制**：每周允许 1 天缓冲，漏一天不清零
- 不强调 streak，不在首屏显示，避免压力
- streak 断了不做任何惩罚提示，只在用户主动查看时展示历史最高记录
