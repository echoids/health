# AI 调用规则定义

## 时间

2026-05-21

## 起点

MVP 产品需求文档已确定,文档中明确了 4 个 AI 触点(初始建议、饮食反馈、周小结、AI 问答),但这些触点的**具体调用规则、输入输出规范、安全边界、成本控制策略**都还未定义。

作者意识到:**AI 是这个产品的核心,规则不定清楚,开发会反复返工,成本也会失控**。因此在进入技术架构设计之前,先把 AI 调用规则定下来。

## 关键讨论

### 讨论 1:模型选型(国内 vs 海外)

作者担心营养建议需要专业性,倾向 OpenAI / Claude。

**关键认知矫正:**

1. **合规层面这不是选择题** — 微信小程序 2024 年起严格审查 AI 生成内容,海外模型基本无法过审
2. **专业性不在底层模型** — 真正决定专业性的是 prompt 工程 + 知识库(如 CFCD 食物成分表)+ 结构化输出。国内主流模型对《中国居民膳食指南》的训练知识已足够
3. **成本差距巨大** — DeepSeek-V3 比 Claude / GPT-4 便宜 10-20 倍,对订阅产品的商业可行性至关重要

最终选型:
- **文本生成主力:** DeepSeek-V3
- **图片识别(二期):** Qwen-VL-Plus

### 讨论 2:饮食反馈的输出格式

三个选项:
- **A. 极简一句话(≤30 字)** — 阅读成本低,但信息量太少,免费/会员难差异化
- **B. 三段式结构化(≤100 字)** ✅ — 数据+评价+建议,UI 可拆分展示,天然差异化
- **C. 自由长度** — 不可控,AI 容易长篇说教

选 B 并改良为 4 字段结构化 JSON,每字段硬约束字数:
```json
{
  "kcal_estimate": 650,
  "nutrient_highlight": "蛋白偏少",
  "evaluation": "主食和油脂偏多",
  "suggestion": "下一餐可以加一份绿叶菜"
}
```

**关键设计:** 免费版只显示后两字段,会员版显示完整 4 字段,**天然形成订阅差异化**,无需人为构造。

### 讨论 3:膳食指南数据是否本地化

作者问"参考《中国居民膳食指南 2022》"是否需要本地提供数据?

**结论:**
- **膳食指南类(指导原则)** — 不需要,模型训练数据已包含,prompt 提及即可作为对齐信号
- **食物成分表(精确数值)** — 需要本地数据库,但 **MVP 阶段不接**,作为二期会员差异化能力

理由:MVP 不强调"精确热量",模型估算误差不影响用户感知;接入 CFCD 是工程量较大的投入,放在二期更合理。

### 讨论 4:初始建议卡片生成方式

三个选项:
- **A. 一次性生成** — 等待时间长(10-20s)
- **B. 流式生成** ✅ — 一句话结论立即显示,其他段落边生成边渲染
- **C. 懒加载** — 首屏只生成结论,其他点开才生成,体验割裂

选 B,流式输出 + 强制 Markdown 模板。

**关键工程问题:** 流式如何保证结构化?答案:让 AI 按固定 Markdown 模板输出,前端按段落标题流式渲染。Prompt 严格约束模板,模型必须按顺序输出。

### 讨论 5:周小结的商业策略

最关键的策略决策。三个选项:
- **A. 完全免费** — 用户体验一致,但会员价值削弱
- **B. 分层差异** ✅ — 免费版规则模板,会员版 AI 个性化
- **C. 试用机制** — 前 2 周免费 AI,易引发"反差感"流失

选 B。理由:
- 日常的 AI 反馈和初始卡片难以做强差异(差异太大易产生"被限制"感)
- 周小结天然是"周期性深度内容",是订阅模式最合理的承载体

### 讨论 6:免费版周小结的丰满度

作者反馈"免费版太简略,会让用户觉得没内容"。

**关键原则:** 免费版增强不能调用 AI(违背成本结构),但可以通过 **更丰富的数据呈现 + 规则化逻辑** 提升内容感。

最终免费版包含:
1. 数据可视化(进度条 + 上周对比)
2. 规则化小发现卡片(15-20 条预设规则触发)
3. 累计成就(连续记录天数等)
4. 按主目标分类的健康小知识池(50 条/目标,避免重复)
5. 克制的升级引导

会员版的不可替代性保留在:**AI 个性化下周建议 + 趋势洞察**(数据视角无法替代)。

### 讨论 7:周小结的成本控制门槛

定下"硬规则":**用户本周记录天数 < 3 → 跳过 AI,即使是会员**。

理由:数据太少时 AI 生成的内容必然是空话,反而损害会员价值感知。这个规则同时控制了成本和体验。

### 讨论 8:AI 问答的对话模式

单轮 vs 多轮?

选 **单轮**。理由:
- 工程简单、成本低
- **多轮容易被"角色扮演"等手段绕过安全规则**
- 每次自动带用户档案上下文,基本能力不打折

### 讨论 9:安全规则的分层

AI 安全不能完全靠 prompt 约束,因为模型也有概率回答错。最终设计三层:

1. **预设拦截层(规则层)** — 关键词命中直接返回固定文案,不走 AI(如自残、处方药)
2. **Prompt 约束层** — 系统提示词中明确禁用词、行为边界
3. **输出审查层** — 重试 + 降级机制,内容安全触发则回退到通用安全文案

## 决策与取舍

| 决策 | 选择 | 放弃了什么 | 理由 |
|---|---|---|---|
| 模型主力 | DeepSeek-V3 | OpenAI / Claude | 合规、中文质量、成本 |
| 饮食反馈输出 | 4 字段结构化 JSON | 自由文本 | 可控、可差异化 |
| 初始卡片生成 | 流式 Markdown | 一次性 / 懒加载 | 体感快、结构稳 |
| 周小结策略 | 免费规则 + 会员 AI 双轨 | 完全免费 / 试用 | 会员价值清晰、成本可控 |
| 免费版周小结 | 数据可视化 + 规则化洞察 | 简单数据列表 | 平衡价值感与零 AI 成本 |
| AI 问答模式 | 单轮 | 多轮 | 安全 + 成本 |
| CFCD 食物表 | MVP 不接,二期再做 | MVP 接入 | 降低开发量,留给会员差异化 |
| 安全边界 | 三层防护(规则+prompt+审查) | 单层 prompt 约束 | AI 也会犯错,需 fail-safe |

## 产出

1. **新文档:** `docs/02-AI调用规则.md` 共 9 章节,涵盖:
   - 总体架构与模型选型
   - 通用安全规则(禁用词、边界、预设拦截)
   - 4 个触点的完整规则(输入/输出/Prompt/失败/成本)

   - 实施优先级(P0 / P1 / 二期)
   - 监控与迭代指标

2. **关键架构原则确立:**
   - 结构化输出优先,字段长度硬约束
   - 长周期内容持久化,避免重复调用
   - Prompt cache 命中率 >80%
   - 预聚合输入数据,token 节约 60%+
   - 安全三层防护(规则 + prompt + 审查)
