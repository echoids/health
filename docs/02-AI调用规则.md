# AI 调用规则文档

本文档定义 AI 健康生活助手中所有 AI 触点的调用规则、输入输出规范、安全边界和成本控制策略。所有 AI 相关开发必须严格遵守本文档。

---

## 1. 总体架构

### 1.1 模型选型

| 用途 | 模型 | 理由 |
|---|---|---|
| 文本生成（所有触点） | DeepSeek-V3 | 中文能力强、合规、成本低 |
| 图片识别（二期扩展） | Qwen-VL-Plus | 视觉能力强，DeepSeek 无视觉模型 |

**不使用海外模型**（OpenAI / Claude / Gemini），原因：微信小程序合规审核要求使用国内备案模型。

### 1.2 AI 触点清单

| 编号 | 触点 | 触发时机 | 调用频次 | 优先级 |
|---|---|---|---|---|
| 1 | 饮食记录即时反馈 | 用户提交饮食记录后 | 高频 | P0 |
| 2 | 初始建议卡片 | 建档完成后 | 每用户 1 次 | P0 |
| 3 | 每周小结（会员版） | 每周日 20:00 | 每用户每周 1 次 | P1 |
| 4 | AI 问答 | 用户主动提问 | 中频 | P1 |

### 1.3 通用原则

1. **结构化输出优先** — 能强制 JSON / Markdown 模板的场景必须强制，避免 AI 自由发挥
2. **字段长度硬约束** — 所有输出字段必须有最大字数限制
3. **持久化结果** — 长周期内容（初始卡片、周小结）必须存数据库，避免重复调用
4. **Prompt Cache** — 所有系统提示词使用 DeepSeek prompt cache 降低成本
5. **预聚合输入** — 不传原始记录给 AI，先做后端聚合
6. **温和措辞** — 不制造焦虑，禁用评判性词汇

## 2. 通用安全规则

### 2.1 全局禁用词

以下词汇在 AI 输出中**严格禁止**：

- **评判类**：超标 / 过量 / 不健康 / 危险 / 警告 / 异常 / 失败 / 退步
- **医疗类**：疾病 / 诊断 / 治疗 / 治愈 / 药物 / 处方
- **绝对类**：应该 / 必须 / 不可以 / 一定要

替代用语：偏多 / 偏少 / 充足 / 不足 / 可以试试 / 不妨

### 2.2 边界规则

AI **不得输出**：
1. 任何疾病诊断结论
2. 药物推荐、保健品推荐、剂量建议
3. 医疗数值的判断（如"血糖 7.2 是否正常"）
4. 对用户身材 / 外貌的评价
5. 替代医生的建议

AI **必须引导就医**的场景：
- 用户提及胸痛、呼吸困难、头晕、出血、昏倒等急性症状
- 用户描述持续性不适
- 用户咨询药物相关问题
- 用户描述孕期 / 产后特殊情况且涉及风险

### 2.3 预设拦截规则

以下场景**不走 AI**，直接返回固定文案：

| 触发关键词 | 返回内容 |
|---|---|
| 自残 / 轻生 / 不想活 | 心理援助热线 010-82951332 + 关怀文案 |
| 处方药名 / 用药剂量 / 几片 / 几克 | 引导咨询医生或药师 |
| 怀孕 + 用药 / 流产 | 引导就医 |
| 减肥药 / 泻药 / 催吐 | 健康提醒 + 引导专业帮助 |

## 3. 触点 1：饮食记录即时反馈

### 3.1 基础信息

| 项 | 值 |
|---|---|
| 触发时机 | 用户提交饮食记录后立即调用 |
| 模型 | DeepSeek-V3 |
| 调用方式 | 同步非流式 |
| 输入 token | ~600 |
| 输出 token | ~150 |
| 超时阈值 | 3 秒 |

### 3.2 输入数据

1. 用户基础档案（年龄、性别、身高、体重、主目标、忌口）
2. 今日已记录饮食（餐次 + 食物列表）
3. 本次饮食内容（食物名称、估算分量、烹饪方式）
4. 当前时段（早 / 午 / 晚 / 加餐）

### 3.3 输出格式

强制 JSON 输出：

```json
{
  "kcal_estimate": 650,
  "nutrient_highlight": "蛋白偏少",
  "evaluation": "主食和油脂偏多",
  "suggestion": "下一餐可以加一份绿叶菜"
}
```

字段约束：
- `kcal_estimate`: 整数
- `nutrient_highlight`: ≤8 字
- `evaluation`: ≤15 字
- `suggestion`: ≤25 字

### 3.4 失败处理

1. 超时 > 3s → 先返回"已记录"提示，反馈结果异步推送
2. 输出格式错误 → 重试 1 次，仍失败只显示"已记录"
3. 内容安全触发 → 降级为静态文案"这一餐已记录,继续保持"

### 3.5 成本控制

1. 系统提示词使用 prompt cache,命中后输入成本降 80%
2. 免费版每日限 3 次,超出只显示"已记录"
3. 会员版无次数限制
4. 1 分钟内重复提交相同内容,复用上次结果

### 3.6 免费 vs 会员

| | 免费版 | 会员版 |
|---|---|---|
| 每日次数 | 3 次 | 无限制 |
| 输出字段 | evaluation + suggestion | 完整 4 字段 |
| 图片识别 | 不支持 | 支持 |

二期扩展：会员版接入 CFCD 食物成分表,提升 kcal 准确度。

## 4. 触点 2：初始建议卡片

### 4.1 基础信息

| 项 | 值 |
|---|---|
| 触发时机 | 用户建档完成后 |
| 模型 | DeepSeek-V3 |
| 调用方式 | 流式输出 stream=true |
| 输入 token | ~800 |
| 输出 token | ~1500-2000 |
| 超时阈值 | 60 秒 |

### 4.2 输入数据

1. 用户完整建档（性别、年龄、身高、体重、主目标、忌口）
2. 快问快答全部结果（运动 / 睡眠 / 饮水 / 外卖零食 / 久坐）
3. 计算得到的 BMI 和 BMI 分类
4. 用户上下文标签（如"年轻久坐型""外卖依赖型"等,由后端规则生成）

### 4.3 输出格式

强制 Markdown 模板,前端按段落流式渲染：

```markdown
## 一句话结论
{≤30字,定调本周整体方向}

## 接下来 7 天,从这 1-2 件事开始
{1-2 条最优先改善项,每条 ≤40 字}

## 饮食
### 餐盘怎么搭
{一段文字,≤80字}

### 推荐多吃
{3-5 类食物,每类带具体例子}

### 减少或避免
{2-4 类,每类带原因,≤15字}

### 一日示例
**早餐:** {简短描述}
**午餐:** {简短描述}
**晚餐:** {简短描述}
**加餐(可选):** {简短描述}

### 替换小技巧
{2-3 条灵活替换建议}

## 运动
{≤80字,针对用户当前运动水平}

## 作息和饮水
{≤80字}

## 7 天小行动
1. {具体可执行行动}
2. {具体可执行行动}
3. {具体可执行行动}
(共 3-5 条)
```

### 4.4 Prompt 关键约束

- 必须严格按模板输出,不增加额外章节
- 一日示例的菜品必须符合用户饮食偏好和忌口
- 7 天小行动必须是行为级、可打勾的(✓"每天喝够 1500ml 水" ✗"健康饮食")
- 全部遵守第 2 章通用安全规则

### 4.5 失败处理

1. 流断开 → 前端缓存已生成部分,提供"重新生成"按钮
2. 超时 60s → 中断流,给用户已生成部分 + 重试入口
3. 内容安全触发 → 整段重新生成,最多重试 2 次,仍失败降级为通用模板

### 4.6 成本控制

1. 系统提示词缓存,命中率应 >90%
2. **生成结果持久化到数据库**,用户复看不调用
3. 用户主动"重新生成"才再次调用,限频 1 天 3 次

### 4.7 免费 vs 会员

| | 免费版 | 会员版 |
|---|---|---|
| 完整生成 | 1 次 | 不限次 |
| 修改档案后更新 | 仅重生成"7 天小行动"段 | 可触发完整重新生成 |
| 主动调整侧重方向 | 不支持 | 支持(如"更专注睡眠改善") |

## 5. 触点 3：每周小结

### 5.1 双轨策略

| | 免费版 | 会员版 |
|---|---|---|
| 调用 AI | 否 | 是 |
| 触发方式 | 后端定时任务模板生成 | 自动生成 + 推送通知 |
| 内容深度 | 数据呈现 + 规则化洞察 | AI 个性化趋势分析 |

### 5.2 免费版规则(无 AI 调用)

**触发时机:** 每周日 20:00 后端定时任务批量生成

**输出内容(模板填充):**

```markdown
## 本周数据
本周记录 5/7 天 · 体重 65.2kg (↓ 0.3kg)

饮水打卡  ████░░░  4 次 / 7 天
运动记录  ██░░░░░  2 次 / 7 天
睡眠记录  █████░░  5 次 / 7 天
完成度    █████░░  顺利 3 · 大致 2 · 没做 0

## 这周的小发现
✓ 体重比上周下降 0.3kg
✓ 睡眠记录天数比上周多 1 天
→ 饮水打卡比上周少 2 次,可以多喝点

## 累计成就
🏅 已坚持记录 21 天
🏅 累计饮水打卡 38 次

## 本周小知识
{按用户主目标分类的预设池随机选 1 条}

💎 升级会员,看 AI 个性化趋势分析和下周建议
```

**小发现规则引擎:**

准备 15-20 条触发规则,例如:
- 本周体重 < 上周 → "体重下降"卡片
- 本周打卡数 > 上周 → "进步"卡片
- 连续记录 ≥ 5 天 → "保持良好习惯"卡片
- 饮水次数 > 6 → "饮水习惯不错"卡片

**小知识池:**

按用户主目标分类,每类 50 条以上,避免重复疲劳。

### 5.3 会员版规则(AI 完整生成)

**基础信息:**

| 项 | 值 |
|---|---|
| 触发时机 | 每周日 20:00 自动生成 + 周一 8:00 推送 |
| 模型 | DeepSeek-V3 |
| 输入 token | ~1500 |
| 输出 token | ~1200 |
| 超时阈值 | 30 秒 |

**输入数据:**

1. 用户档案 + 主目标
2. 本周预聚合数据(不传原始记录):
   - 饮食记录次数 / 频次分布 / 主要食物类别统计
   - 体重时间序列
   - 饮水 / 运动 / 睡眠 / 久坐打卡统计
   - 每日完成度确认结果(顺利 / 大致 / 没执行 各占比)
3. 每周感受反馈(精力 / 睡眠 / 消化对比上周,如用户填了)
4. 上周小结的"下周建议"(用于对比本周执行情况)

**输出格式:**

```markdown
## 本周一句话
{≤30字 整体评价}

## 这周你做到了什么
{2-3 条具体的正向行为}

## 趋势观察
{结合感受反馈和数据的 2-3 条洞察}

## 可以再优化的地方
{1-2 条,温和措辞}

## 下周建议
1. {具体可执行}
2. {具体可执行}
(2-3 条)
```

**Prompt 关键约束:**

- 优先肯定,再给建议
- 用户填了感受反馈 → 必须结合感受讨论
- 用户没填感受反馈 → 纯数据视角,不假设感受
- 下周建议必须可追踪(能对应到下周打卡项)

**失败处理:**

1. AI 调用失败 → 降级为免费版模板小结,标注"AI 服务暂时不可用"
2. 超时 / 重试 1 次仍失败 → 同上降级
3. 内容安全触发 → 重新生成最多 2 次

**成本控制(关键):**

1. **生成结果持久化** — 用户复看不再调用
2. **门槛规则** — 本周记录天数 < 3 → 跳过 AI,给"鼓励继续记录"的简单卡片(即使是会员)
3. **预聚合** — 后端先把原始记录聚合成结构化统计,再传给 AI,token 节约 60%+
4. 系统提示词缓存

### 5.4 用户关怀逻辑

- 连续 2 周记录 < 3 天 → 推送温和消息("最近忙吗?随手记一笔也可以"),不强迫恢复

## 6. 触点 4：AI 问答

### 6.1 基础信息

| 项 | 值 |
|---|---|
| 触发时机 | 用户在问答入口主动提问 |
| 模型 | DeepSeek-V3 |
| 调用方式 | 同步非流式(或可选流式) |
| 对话模式 | **单轮**(不带历史对话上下文) |
| 输入 token | ~500 |
| 输出 token | ~200 |
| 超时阈值 | 8 秒 |

**单轮设计理由:** 多轮对话容易被"角色扮演"等手段绕过安全规则。每次调用自动带用户档案上下文即可。

### 6.2 输入数据

1. 用户当次提问(限制 200 字以内)
2. 用户基础档案(性别、年龄、主目标、忌口)
3. 最近 3 天饮食记录摘要(让 AI 能基于近况回答)
4. 时段信息(早 / 午 / 晚,影响"现在吃什么"类问题)

### 6.3 输出格式

自由文本,限制 ≤200 字。

Prompt 约束:
- 优先直接回答问题
- 必要时给 1-3 条可执行建议
- 避免长篇说教

### 6.4 Prompt 关键约束

```
角色:参考《中国居民膳食指南》的健康助手
范围:仅回答饮食、运动、作息、饮水、生活习惯类问题

不做:
- 不诊断任何疾病
- 不推荐药物或保健品
- 不给出具体医疗数值判断
- 不评价用户的身材/外貌

风格:
- 简短可执行
- 不超过 200 字
- 大白话,不用专业术语
- 避免"应该""必须",用"可以试试""不妨"

边界检测:
- 提到症状 → 强制引导就医
- 提到药物/保健品 → 引导咨询医生或药师
- 提到极端节食/暴食/催吐 → 表达关心 + 引导专业帮助
- 提到自残/轻生 → 提供心理援助热线,不参与讨论
```

### 6.5 预设拦截(不走 AI)

见第 2.3 节通用拦截规则。

### 6.6 失败处理

1. AI 调用失败 → 返回"AI 助手暂时忙,请稍后再问"
2. 超时 8s → 中断 + 重试提示
3. 内容安全触发 → 返回通用安全文案"这个问题我不太适合回答,建议咨询专业人士"

### 6.7 成本控制

1. 用户输入预处理:超过 200 字截断 + 提示
2. **每问题缓存** — 同一用户 5 分钟内问相同问题,返回缓存结果
3. 系统提示词缓存

### 6.8 免费 vs 会员

| | 免费版 | 会员版 |
|---|---|---|
| 每日次数 | 3 次 | 20 次(防滥用) |
| 上下文 | 仅档案 | 档案 + 近 3 天记录摘要 |
| 回复深度 | 通用建议 | 结合个人记录的针对性建议 |

## 7. 成本估算

### 7.1 单次调用成本(DeepSeek-V3 定价)

按输入 ¥0.5/百万 token、输出 ¥2/百万 token、cache 命中 ¥0.1/百万 token 估算:

| 触点 | 输入 tokens | 输出 tokens | 单次成本(预估) |
|---|---|---|---|

| 周小结(会员) | 1500(cache 90%) | 1200 | ¥0.0026 |

|---|---|---|
| 饮食反馈 | 800 免费 × 90 + 200 会员 × 300 | ¥53 |

| 周小结 | 200 会员 × 4 | ¥2.1 |
| AI 问答 | 800 免费 × 90 + 200 会员 × 600 | ¥96 |
| **合计** | | **~¥152/月** |

实际成本会因用户活跃度、记录习惯波动,初步预算按 **每会员用户每月 AI 成本 ¥1-2** 估算。

## 9. 监控与迭代

### 9.1 必须监控指标

- 每个触点的调用成功率
- 每个触点的平均响应时长
- 内容安全触发频次和触发关键词分布
- 每用户每日 AI 调用次数分布(发现异常用户)
- AI 输出格式错误率(JSON 解析失败 / Markdown 模板偏离)

### 9.2 迭代节奏

- 上线后第 1 周:每日复盘 AI 输出质量,调整 prompt
- 第 2-4 周:每周复盘,优化失败处理和成本结构
- 稳定后:每月评估一次模型切换的必要性
